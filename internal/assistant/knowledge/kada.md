# Kada 平台说明

> 本文档是 Kada 短链接平台的产品与技术说明，随 AI 助手一起编译进二进制，每次提问时作为参考资料发给模型，用来回答用户关于 Kada 的问题。

## 一、Kada 是什么

Kada 是一个**短链接管理与数据分析平台**。用户可以把长网址转换成短链接，对短链接进行分类组织，并查看短链接被点击的数据统计（点击量、趋势、访客来源、设备平台等）。

平台只支持一种登录方式：**手机号 + 短信验证码**，登录后使用 JWT 令牌访问接口。未注册过的手机号会在首次登录时自动创建账号，因此没有单独的注册流程。登录页需要先通过一张图形验证码才能请求短信。界面支持中文/英文双语，并提供明暗主题切换。

## 二、核心功能

- **短链接管理**：创建、编辑、停用、删除短链接，支持批量删除、批量打标签
- **自定义短码**：创建链接时可以指定自己想要的短码（如 `kada.click/r/launch`），不指定则系统随机生成
- **自定义域名**：用户可以绑定自己的域名来生成短链，绑定前需要通过 DNS TXT 记录验证域名所有权
- **访问密码**：可以给短链设置访问密码，访客打开后需要输入密码才能跳转
- **过期时间**：可以给短链设置有效期，过期后访问会显示错误页面而不是跳转
- **文件夹与标签**：用文件夹（folders）和标签（tags）组织大量链接，支持批量操作
- **工作区（workspaces）**：按团队或项目对链接进行分组
- **UTM 参数与模板**：为链接附加 UTM 营销参数（来源、媒介、活动等），可保存为模板复用
- **链接预览与二维码**：支持链接预览图、生成二维码、导出 CSV
- **点击分析看板**：点击总数、每日趋势、平台分布（系统/浏览器）、访客明细、原始事件日志
- **开放 API**：用户可以创建个人 API Token，通过接口程序化地管理短链

## 三、技术架构

Kada 由以下部分组成：

| 组件 | 技术 | 职责 |
|---|---|---|
| Go 后端 | Go 1.26 + Gin + GORM，端口 8080 | HTTP 接口、短链跳转、业务逻辑 |
| 前端 | Vite + React 19 + React Router + TypeScript + SWR + Tailwind，构建为静态文件由 nginx 直接托管 | 用户界面 |
| PostgreSQL 16 | 主数据库 | 业务数据的唯一真相源 |
| Redis 7 | 缓存 | 短码缓存、限流计数 |
| Kafka 3.8 | 消息队列 | 点击事件异步落库 |
| Worker（Go） | 独立进程，无 HTTP 端口 | 消费 Kafka 的点击事件并写入数据库 |
| Nginx | 反向代理，端口 80 | 统一入口：`/api/` 和 `/r/` 转发后端，其余转发前端 |
| AI 助手（Go） | 与 API 同一个进程，Eino | 对话、工具调用与平台问答；说明文档随二进制编译，随 API 一起部署，没有独立服务 |

后端代码分层为 **Handler（HTTP 层）→ Service（业务逻辑）→ Entity（数据库模型）**。Handler 不直接碰数据库，Service 不接触 HTTP 上下文。数据归属校验在 Service 层完成：查询时始终把 `user_id` 放进 WHERE 条件，绝不信任客户端传来的 ID。

### 点击事件为什么是异步的

短链跳转是**热路径**，必须极快且不能因为数据库忙而失败；而点击统计是**冷路径**，允许延迟一秒左右。因此访问短链时：先把点击事件发到 Kafka 再立即跳转，Worker 异步消费写入 `click_logs` 并累加计数。如果 Kafka 不可用，会降级为直接写数据库，保证统计不丢。

## 四、短链接的访问流程

访客打开短链接（如 `https://kada.click/r/abc123`）时：

1. Nginx 把 `/r/:code` 请求转给 Go 后端
2. 后端先查 Redis 缓存，未命中再查 PostgreSQL 中 `short_code` 对应的有效链接，查到后回填 Redis
3. 判断链接状态：已停用或已过期 → 错误页面；设有访问密码 → 密码验证页；需要引导页（如 App 深链）→ 中间引导页
4. 正常链接：记录一次点击事件（发 Kafka），然后 302 重定向到原始网址

短链只接受 `http` 和 `https` 开头的目标地址，`javascript:`、`data:` 等危险协议会被拒绝。

## 五、数据分析说明

分析看板（前端"洞察"菜单）包含：

- **分析（overview）**：点击总数等汇总指标
- **时间（trend）**：每日点击趋势
- **客户（customers）**：访客明细列表
- **事件（events）**：原始点击事件日志，包含平台（platform）、IP、来源页（referer）

分析数据是**按需实时查询** `click_logs` 表得出的，目前没有预聚合表，数据量很大时这是首先要优化的地方。由于点击经 Kafka 异步落库，刚产生的点击在统计上可能有 1 秒左右的延迟，属于正常现象。

## 六、AI 助手能力

平台内置 AI 助手（侧边栏"AI 助手"菜单），能力包括：

- **自然语言对话**：流式输出（SSE），逐字返回回答
- **创建短链**：直接把链接发给 AI，说"帮我转成短链"，AI 会调用短链服务创建并返回短链接
- **查询数据概览**：询问"我有多少链接""最近点击情况"，AI 会调用数据概览接口回答
- **平台问答**：AI 每次提问都会读到随程序一起发布的说明文档（就是本文档），因此能回答关于 Kada 功能和使用方式的问题
- **工具调用**：AI 可以查询当前时间、做简单计算，也能**以当前登录用户的身份**查询短链总览和创建短链（工具在同一个进程内直接调用业务服务，用的是本次请求的登录用户，不需要额外配置服务令牌）

AI 助手采用**单会话模式**：每个用户只保留当前一个会话，对话有上下文记忆；点击"重新开始"会清空当前会话并开启新会话。会话记录存放在主数据库 PostgreSQL 里，说明文档则随二进制一起发布，没有额外的缓存层。

## 七、常见问题（FAQ）

**问：短链接的格式是什么？**
答：正式环境为 `https://kada.click/r/{短码}`，例如 `https://kada.click/r/abc123`。短码默认随机生成，也可在创建时自定义。

**问：为什么我在本地开发环境访问 kada.click 的短链打不开？**
答：`kada.click` 域名的 DNS 指向公网服务器，不会解析到本机。本地测试短链跳转应使用 `http://127.0.0.1:8080/r/{短码}`，且需要本地 Go 后端正在运行。部署到服务器后正式域名才可正常使用。

**问：短链设置了密码或过期时间后会怎样？**
答：设密码的短链访问时先进入密码页，验证通过才跳转；过期短链访问时显示错误页面，不再跳转。过期判断发生在访问时（读取时计算），系统没有定时清理任务。

**问：自定义域名怎么绑定？**
答：在域名管理页面添加域名后，需要到域名 DNS 服务商处添加系统提供的 TXT 验证记录，验证域名所有权通过后，该域名才能用于生成短链。

**问：API Token 怎么使用？**
答：在设置中创建 API Token（令牌明文只在创建时显示一次，数据库只存哈希），之后调用开放接口时在请求头携带该令牌即可程序化管理短链。令牌可以设置名称、查看最后使用时间。

**问：删除链接、文件夹、用户后数据会怎样？**
答：删除短链会级联删除它的点击日志；删除文件夹或工作区只会把其中链接的归属置空（链接本身保留）；删除用户会级联删除其文件夹、标签、域名、模板和令牌，但链接会被置空归属而保留，避免公开短链失效。

**问：密码安全是怎么处理的？**
答：账号密码（历史遗留字段）和短链访问密码使用 bcrypt 哈希存储；短信验证码、图形验证码答案和 API Token 使用 SHA-256 哈希存储，明文都不会落库，也不会写进日志。

**问：限流策略是怎样的？**
答：分两层。第一层是基于 Redis 的滑动窗口限流，分三档：普通接口常规限制、登录认证接口严格限制、短链跳转接口较高吞吐限制；Redis 不可用时限流会放行（fail open），优先保证可用性。
第二层是短信发送的三重配额，写在数据库里，因此即使 Redis 挂了也依然生效：同一手机号 60 秒内只能发一条、每天最多 10 条；同一 IP 每小时最多 10 条、每天最多 30 条。此外发送短信前必须先答对一张 5 分钟有效的图形验证码，且验证码是一次性的（无论发送成功还是被配额拒绝都会被消耗）。

## 八、本地开发须知

- 启动后端：`cd backend && go run ./cmd/server/main.go`（端口 8080）；启动前端：`cd frontend && npm run dev`（端口 3000）
- 一键启动全部服务（含数据库等）：`docker compose up -d`
- 数据库表结构由 GORM 模型自动迁移（AutoMigrate），只增不删，可重复执行
- AI 助手没有独立服务：它随 API 进程一起启动，`/api/ai/*` 由同一个二进制提供
- AI 说明文档：`internal/assistant/knowledge/` 下的 Markdown 会在编译时嵌入二进制，每次提问时整篇作为参考资料发给模型；改完文档重新编译即可生效，不需要入库、切块或迁移
- AI 助手需要配置的环境变量：`DEEPSEEK_API_KEY`（对话模型密钥）；`AI_CHAT_MODEL`、`DEEPSEEK_BASE_URL`、`AI_MAX_TOKENS` 可选
